# Deploying to Azure App Service

Two Linux **Web Apps for Containers** on one App Service plan, images in Azure Container Registry:

```
browser ──https──▶ <prefix>-web  (nginx :80)  ──https /api, /healthz──▶ <prefix>-api  (uvicorn :8080)
                   static React build                                  semantic layer + data/source
```

The browser only ever talks to `<prefix>-web`, same-origin, exactly as in local dev and on Vercel.

## One-time setup

1. **Install the Azure CLI** (2.60 or newer): `winget install -e --id Microsoft.AzureCLI`, then open a new terminal.
2. **Sign in and pick the subscription:**
   ```bash
   az login
   az account set --subscription "<subscription name or id>"
   ```
   You need Contributor plus **User Access Administrator** (or Owner) on the subscription or resource group,
   because the script grants each app's managed identity `AcrPull` on the registry.
3. **Secrets, locally** (never committed, never put in an image):
   - `.env` beside this project's README: LLM keys (`GROQ_API_KEY`, `NTT_GEMINI_KEYS`, `NTT_ANTHROPIC_KEY`,
     `NTT_OPENROUTER_KEY`…) and any other `NTT_*` setting. Every `KEY=VALUE` here becomes an App Setting on the API.
   - `.demo-accounts.json`: generated by `python -m api.scripts.setup_demo_accounts`. The script uploads it
     to an Azure Files share mounted into the API. Without it, set `NTT_EXECUTIVE_EMAIL`,
     `NTT_EXECUTIVE_PASSWORD` and `NTT_ACCESS_SECRET` in `.env`, or nobody can sign in.

## Deploy (and every redeploy)

From `ntt-command-centre/`, in **Git Bash**:

```bash
AZ_PREFIX=nttcc-syren ./deploy/azure/deploy.sh
```

`AZ_PREFIX` must be globally unique (it becomes `<prefix>-web.azurewebsites.net`). Optional overrides:

| Variable | Default | |
|---|---|---|
| `AZ_LOCATION` | `eastus` | Azure region |
| `AZ_RG` | `<prefix>-rg` | resource group |
| `AZ_SKU` | `B2` | plan size; B1 (1.75 GB) is tight for pandas + scikit-learn, use P0v3/P1v3 for production |
| `TAG` | `<git sha>-<timestamp>` | image tag |

The first run takes roughly 10 minutes, most of it building images in ACR and the API's first start, which
trains the closure model. It prints the URLs when both apps report healthy:

```
✓ deployed 1508cc3-20261001083000
  web  https://nttcc-syren-web.azurewebsites.net
  api  https://nttcc-syren-api.azurewebsites.net
```

Re-running rebuilds both images, re-uploads `.env` and `.demo-accounts.json`, and repoints the apps.

## What the script configures

| | API app | Web app |
|---|---|---|
| Image | `ntt-api:<tag>` (root `Dockerfile`) | `ntt-web:<tag>` (`web/Dockerfile`) |
| `WEBSITES_PORT` | `8080` | `80` |
| Other settings | `.env` keys, `NTT_ALLOWED_ORIGINS=<web url>`, `NTT_DEMO_ACCOUNTS_FILE=/mnt/accounts/demo-accounts.json`, `WEBSITES_CONTAINER_START_TIME_LIMIT=600` | `API_UPSTREAM=<api url>` |
| Health check | `/healthz` | `/` |
| Both | managed-identity ACR pull (no registry password), HTTPS only, Always On, TLS 1.2+, FTPS off | |

## After deploying

- **Logs:** `az webapp log config -n <prefix>-api -g <prefix>-rg --docker-container-logging filesystem` once,
  then `az webapp log tail -n <prefix>-api -g <prefix>-rg`.
- **Changing a secret:** edit `.env` and re-run the script, or use Portal → API app → *Environment variables*.
  For production, move keys to Key Vault and reference them as `@Microsoft.KeyVault(SecretUri=...)`.
- **Custom domain:** add it to the **web** app (Portal → *Custom domains*, free managed certificate), then add
  that origin to `NTT_ALLOWED_ORIGINS` on the API.
- **Lock the API down (optional):** the web app is its only legitimate caller. Portal → API app →
  *Networking → Access restrictions*, and allow only the web app's outbound IPs
  (`az webapp show -n <prefix>-web -g <prefix>-rg --query outboundIpAddresses`).
- **Data updates:** the xlsx/csv files in `data/source` are baked into the API image. Replace them and re-run the script.

## Things to know

- **As-of date** follows the container's clock (UTC) and is read when the process starts. A restart picks
  up the new day. Set `NTT_AS_OF=YYYY-MM-DD` in `.env` to pin a demo date.
- **The closure-action cache** (`data/generated`) is on the container's disk, so it resets on restart. The app
  tolerates that and re-refines on demand.
- **One worker, one instance.** The model is held in memory per process. Scale **up** (bigger SKU), not out.
- **Cold start** is a few minutes. Always On (Basic tier and above) keeps the app warm afterwards.
- **Tear down everything:** `az group delete -n <prefix>-rg`.
